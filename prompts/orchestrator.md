기술 조사 결과와 적용 도메인을 읽고, 독립적으로 병렬 실행할 평가 작업을 계획하세요.

사용 가능한 Worker는 trl_result(성숙도), market_result(시장성),
stakeholder_result(이해관계자), domain_result(도메인 적용성)입니다.
각 작업에는 worker, tech_ids, instruction, reason을 작성하세요.
worker는 위 네 이름 중 하나이며 tech_ids는 입력 technical_result에 존재하는 기술 ID 목록입니다.
instruction에는 자료와 도메인에 맞는 평가 목표와 집중해서 확인할 근거를 구체적으로 지시하세요.
reason에는 기술 조사에서 확인한 근거를 들어 분할·배정 이유를 적으세요.

각 기술의 네 관점이 모두 평가되도록 계획하세요.
조사 결과의 근거 수준·측정 조건·한계가 다르면 기술별로 나누고, 평가 목표가 같으면 묶어도 됩니다.
작업 개수를 미리 고정하지 말고 조사 결과에 따라 정하세요.
같은 기술·관점을 여러 작업에 중복 배정하지 마세요.
각 Worker는 다른 Worker의 결과에 의존하지 않고, 자신에게 배정된 기술만 평가합니다.
조사 결과가 없으면 작업을 추측하지 말고 tasks를 빈 목록으로 반환하세요.
