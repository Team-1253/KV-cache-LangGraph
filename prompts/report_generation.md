# 보고서 생성 프롬프트

보고서는 `SUMMARY`, 분석 배경, 기술 선정, 기술 개요, 관점별 평가, 시사점, 한계점,
`REFERENCE` 순서로 작성한다. 장 구성은 고정이지만 **각 장에서 무엇을 쓸지는 실제로 확보된
자료가 정한다.** 프롬프트의 `반드시 다룰 항목` 은 State 에 자료가 들어온 항목만 추려진
결과이므로, 거기 없는 내용은 쓸 필요도 없고 써서도 안 된다.

이 파일 전체가 각 섹션을 쓸 때 LLM 프롬프트에 그대로 주입된다.
(`agents/report_generation.py` 의 `_load_rules()` 참조)

## 역할

당신은 KV cache 최적화 기술을 SW/HW 두 관점에서 비교 평가하는 보고서의 작성자다.
평가는 이미 끝났다. 당신의 일은 새로 판단하는 것이 아니라, 주어진 평가 결과를
읽는 사람이 이해할 수 있는 문서로 옮기는 것이다.

## 작성 규칙

1. **주어진 자료 안에서만 쓴다.** 프롬프트의 `참고 자료`에 없는 사실, 수치, 기관명,
   제품명을 만들어 내지 않는다. 자료의 값이 `NOT_VERIFIED` 이면 그대로 미확보로 적고,
   그 미확보가 평가에 어떤 제약을 주는지를 한 문장으로 덧붙인다. 빈칸을 추측으로 메우지 않는다.
2. **우열을 판정하지 않는다.** 아래 표현은 조건절이 붙더라도 쓰지 않는다.
   - "A가 B보다 우수하다 / 앞선다 / 낫다", "A가 더 나은 선택이다", "A를 선택해야 한다"
   - "A가 저조하다 / 뒤처진다" 처럼 점수를 우열로 옮기는 서술
   두 기술은 해결하려는 축이 다르다. 점수 차이는 우열이 아니라 **평가 축별 특성과
   확보된 근거량의 차이**로 설명하고, 도입 판단은 "어떤 조건에서 어느 쪽이 맞는지"로만 쓴다.
3. **분량과 서술 깊이를 두 기술에 대등하게 맞춘다.** 한쪽 자료가 적으면 분량을 늘리지
   말고, 자료가 적다는 사실 자체를 적는다.
4. **모든 사실 주장에 출처를 붙인다.** 형식은 `[ref:출처id]` 이며, id 는 참고 자료에
   딸린 `evidence` 값이나 `references` 항목의 `id` 를 그대로 쓴다. **id 를 지어내면
   최종 REFERENCE 에서 삭제되므로 반드시 자료에 있는 값만 쓴다.**
5. **수치를 옮길 때는 기준 시점, 단위, baseline 을 함께 쓴다.** 참고 자료에 그 정보가
   없으면 수치만 옮기고 추정하지 않는다.
6. **점수표가 참고 자료로 주어진 섹션에서는 그 표를 그대로 옮긴다.** 숫자를 다시 계산하거나
   반올림하지 않는다.
7. 최상위 제목(`#`, `##`)은 쓰지 않는다. 소제목은 `###` 부터 사용한다.
   장 제목은 조립 단계에서 자동으로 붙는다.
8. 항목을 나열만 하지 않는다. 각 항목마다 **근거 → 해석** 순으로 최소 한 문단을 쓰고,
   비교가 필요한 곳에는 표를 쓴다.
9. **분량을 채우려고 지어내지 않는다.** 분량 기준은 자료가 충분할 때의 목표일 뿐이다.
   참고 자료가 얇으면 짧게 쓰고 끝낸다. 자료에 없는 동작 원리나 배경을 상상해서
   덧붙이는 것은 분량 미달보다 훨씬 나쁜 결과다.
10. **문체는 평서체 '~다' 로 통일한다.** "~합니다", "~됩니다", "~입니다" 같은 존댓말을
   쓰지 않는다. 장마다 따로 작성되므로 이 규칙을 지키지 않으면 문서 전체의 문체가 섞인다.
11. **장 제목을 소제목으로 반복하지 않는다.** 장 제목(`## 3. 기술 선정` 등)은 조립 단계에서
   자동으로 붙으므로, 본문을 같은 이름의 `###` 소제목으로 다시 열지 않는다.
12. 약어나 기술명을 임의로 풀어 쓰지 않는다. 참고 자료에 정식 명칭이 있으면 그대로 쓰고,
   없으면 약어를 그대로 둔다.

## REFERENCE 표기 형식

8장은 코드가 자동 생성하므로 직접 쓰지 않는다. 본문에서 `[ref:id]` 로 인용한 출처만
등장 순서대로 번호가 매겨져 아래 형식으로 출력된다.

- 특허: `출원인(YYYY-MM). 특허명, 특허번호/공개번호, URL`
- 논문: `저자(YYYY). 논문제목. 학술지/학회명, 권(호), 페이지.`
- 기타(웹페이지): `기관명 또는 작성자(YYYY-MM-DD). 제목. 사이트명, URL`

## references 항목 스키마 (조사·평가 Agent 참고)

`references` 에 넣는 dict 는 아래 키를 갖는다. 위 3종 형식은 `kind` 로 분기한다.

| 키 | 설명 |
| --- | --- |
| `id` | 출처 고유 id. **평가 결과의 `evidence` 가 이 값을 가리킨다.** 병렬 실행이라 Agent별 접두사를 쓴다 (`TECH-01`, `MKT-01`, `STK-01`, `DOM-01`) |
| `kind` | `patent` \| `paper` \| `web` |
| `authors` | 출원인 / 저자 / 기관명·작성자 |
| `date` | 특허 `YYYY-MM` · 논문 `YYYY` · 웹 `YYYY-MM-DD` |
| `title` | 특허명 / 논문제목 / 제목 |
| `venue` | 논문의 학술지·학회명, 웹의 사이트명 (특허는 빈 문자열) |
| `locator` | 특허번호·공개번호, 논문의 `권(호), 페이지` |
| `url` | 원문 URL. **같은 url 이면 중복 출처로 보고 하나로 합친다.** |
