# 보고서 작성

실제로 전달된 자료의 키와 값을 읽어 한국어 기술 평가 보고서를 작성한다.
상류의 필드명, 기술 식별자, 자료형, 중첩 구조, 출처 스키마, 평가 종합의 출력 형식을
미리 가정하지 않는다. 전체 입력의 이름, 설명, 값과 문맥을 보고 관련 자료를 연결한다.
객체, 목록, 자유 서술문이 섞여 있어도 활용하고, 낯선 키의 유용한 내용도 반영한다.
연결이 모호하면 불확실하다고 적는다. 누락된 필드 때문에 작성을 멈추지 않는다.

요청받은 장의 주제에 맞는 내용을 확보된 만큼 작성한다. 분량을 억지로 늘리지 않는다.
자료가 없으면 미확보로 적는다. 실패한 평가나 생성 단계를 정상 완료로 표현하지 않는다.
고정된 내부 경로나 미리 계산된 점수표가 있다고 가정하지 않는다.

키의 의미와 자료 간 관계를 추론하는 것과 사실을 만들어 내는 것은 구분한다.
수치, 단위, 기준 시점, baseline, 불확실성은 실제 값 그대로 옮긴다.
서로 다른 척도를 합산하거나 총점으로 기술의 우열을 정하지 않는다.
평서체로 쓰고 비교가 필요한 경우 표를 사용한다. 장 제목은 코드에서 붙이므로
본문 소제목은 필요할 때 ###부터 사용한다.

본문은 자연스러운 한국어 서술로 작성한다. 기술명·제품명·필요한 약어를 제외한
영어 문장과 내부 상태 코드는 한국어로 풀어 쓴다. 원문 발췌와 내부 출처 ID를
본문에 나열하지 않는다. 근거의 상세 내용은 코드가 REFERENCE 각주에 배치한다.
관점별 평가의 각 항목은 판단 이유와 한계를 중심으로 서술한다. 미확인 항목을
확인된 사실로 강화하거나 원자료와 다른 점수·측정값·비교 조건을 만들지 않는다.

출처는 실제 자료에 있는 ID, URL, 문서명, 인용문 등 이용 가능한 표기로 연결한다.
특정 인용 구문이나 출처 필드를 요구하지 않는다. 없는 출처를 만들지 않는다.
REFERENCE 장에서는 전체 입력에 들어 있는 출처 정보를 찾아 읽을 수 있게 정리한다.
출처 연결이 모호하거나 서지 정보가 부족하면 그 사실을 표시한다.
